cpp_utils
A header-only utility library written in modern C++ (C++23 or above).
Named Requirements: OperatorFunctorSet

An OperatorFunctorSet is a structural type that encapsulates and unifies type constraints and behavior for overloaded operators of a user-provided class type. utils::*_op accepts OperatorFunctorSet(s) as template parameter and translates them into operator overloads, which is then expected to be inherited as part of the mixin pattern. Its use is most appropriate in a scenario where the child type is a wrapper around an underlying type for which such operations are well-defined.

Requirements

An OperatorFunctorSetTemplate is a class template declared as such by the library in the following format:

{c++}
template <typename Op1, ..., typename OpN, typename Traits1, ..., typename TraitsM>
struct OperatorFunctorSetTemplate;

Each OpI corresponds to an operator supported by the template, denoted by @_I; and a trait set (from Traits1 to TraitsM), denoted by Traits_I. All overloadable operators are classified into types, each corresponding to a trait set given by a fixed template parameter name, as specified below:

Case Type Trait Parameter Name Remarks
1 Binary operator BinaryTraits This excludes assignment operators.
2 Assignment operator AsgTraits -
3 Unary operator UnaryTraits This excludes prefix operators.
4 Prefix operator PrefixTraits -

An instance of such a template is an OperatorFunctorSet for a class type T if it satisfies all requirements below, for each $I\in[N]$.

Notations

Expression Definition
op_i A const-qualified object of OpI
a, b An expression of any value category and any (possibly cv-qualified) referencable type
t An expression of any value category and type T (possibly cv-qualified)
Type Definition
A decltype(a)&&
B decltype(b)&&
TR decltype(t)&&
Template Definition
R Traits_I::result
C Traits_I::constraint

Type Requirements

  • OpI and Traits must be structural types.

Supported Operations

Expression (exp) Semantics
(for Case 1)
op_i(T::to_underlying(a), T::to_underlying(b)) 		Conditions
  • OpI is not utils::disable_op.
  • At least one of a and b is of type T, discarding cv-qualifiers. Let t be the first expression (in a and b) that meets this requirement.
  • C<TR, A, B>::value is true.
  • exp is well-formed.
Effects
  • If R<A, B>> is utils::deduce_t, a @_I b is equivalent to exp; otherwise, it is equivalent to static_cast<R<TR, A, B>>(exp).
(for Case 2)
op_i(T::to_underlying(a), T::to_underlying(b)) 		Conditions
  • OpI is not utils::disable_op.
  • a is or is a reference to an object of type T.
  • C<A, A, B>::value is true.
  • exp is well-formed.
Effects
  • a @_I b is equivalent to exp, a (disregarding overloading of the comma operator).
(for Case 3)
op_i(T::to_underlying(t)) 		Conditions
  • OpI is not utils::disable_op.
  • C<TR>::value is true.
  • exp is well-formed.
Effects
  • @_I a or a @_I, whichever is applicable, is equivalent to exp if R<TR> is utils::deduce_t, or static_cast<R<TR>>(exp) otherwise.
(for Case 4)
op_i(T::to_underlying(t)) 		Conditions
  • OpI is not utils::disable_op.
  • C<TR>::value is true.
  • exp is well-formed.
Effects
  • @_I a is equivalent to exp, a (disregarding overloading for the comma operator).

Remarks

For brevity, in library documentation, when a template parameter Traits is required to be an OperatorFunctorSet for utils::*_op, the meaning changes slightly. In this case, Traits is required to be an OperatorFunctorSet for each descendant of utils::*_op that the user uses any of its supported operators on.
