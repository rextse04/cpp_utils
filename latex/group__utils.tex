\doxysubsection{Detailed Description}
Determines if a type is integer like. 

Conversion to references to underlying type.

Default-\/initializes {\ttfamily under\+\_\+}.

Get a reference to the underlying object of {\ttfamily x}.

Determines if {\ttfamily From} can be converted to {\ttfamily To} without loss of information.

Extends the definition of {\ttfamily epsilon} in {\ttfamily std\+::numeric\+\_\+limits} to integral types.

Determines if {\ttfamily T} and {\ttfamily U} have the same sign. Calculation is based on {\ttfamily TInfo} and {\ttfamily UInfo}, which default to respective instantiations of {\ttfamily std\+::numeric\+\_\+limits}. They can be replaced by class types that provide the same interface as {\ttfamily std\+::numeric\+\_\+limits}.

Similar to usual arithmetic conversion, except that the promotion step is replaced by {\ttfamily utils\+::sane\+\_\+promotion}.

Determines the width of {\ttfamily T} based on {\ttfamily Info}.

The construct is used by the library to determine if a type (ignoring cv-\/qualifiers) is integer like. The program is ill-\/formed, no diagnostics required, if the user specializes {\ttfamily \mbox{\hyperlink{group__utils_structutils_1_1is__integer__like}{utils\+::is\+\_\+integer\+\_\+like}}} such that there exists a type {\ttfamily T} where {\ttfamily std\+::remove\+\_\+cvref\+\_\+t\texorpdfstring{$<$}{<}T\texorpdfstring{$>$}{>}} is not a integer-\/like type (as specified by the standard library), but {\ttfamily \mbox{\hyperlink{group__utils_structutils_1_1is__integer__like}{utils\+::is\+\_\+integer\+\_\+like}}\texorpdfstring{$<$}{<}T\texorpdfstring{$>$}{>}\+::value} is {\ttfamily true}.

\char`\"{}width\char`\"{} here is defined as the number of bits that participate in the determination of the value of the significand (mantissa) in base-\/2 scientific notation. 
\begin{DoxyTemplParams}{Template Parameters}
{\em Info} & A type which provides the interface of {\ttfamily std\+::numeric\+\_\+limits} and gives information about {\ttfamily T}.\\
\hline
\end{DoxyTemplParams}
Given any types {\ttfamily T} and {\ttfamily U}, let {\ttfamily TD} and {\ttfamily UD} be {\ttfamily std\+::decay\+\_\+t\texorpdfstring{$<$}{<}T\texorpdfstring{$>$}{>}} and {\ttfamily std\+::decay\+\_\+t\texorpdfstring{$<$}{<}U\texorpdfstring{$>$}{>}} respectively. Their {\ttfamily \mbox{\hyperlink{group__utils_structutils_1_1sane__common__type}{sane\+\_\+common\+\_\+type}}} {\ttfamily C} is determined through the following steps\+:
\begin{DoxyEnumerate}
\item If any of {\ttfamily TD} and {\ttfamily UD} is not specialized for {\ttfamily std\+::numeric\+\_\+limits}, {\ttfamily C} is {\ttfamily std\+::common\+\_\+type\+\_\+t\texorpdfstring{$<$}{<}T, U\texorpdfstring{$>$}{>}}.
\item Otherwise, if {\ttfamily TD} and {\ttfamily UD} have different widths, {\ttfamily C} is the one with the greater width.
\item Otherwise, if at least one of {\ttfamily TD} and {\ttfamily UD} is unsigned, {\ttfamily C} is the first unsigned type out of the two.
\item Otherwise, {\ttfamily C} is {\ttfamily TD}.
\end{DoxyEnumerate}

In the above, the definition of {\ttfamily width} is identical to that in {\ttfamily \mbox{\hyperlink{group__utils_structutils_1_1width__of}{utils\+::width\+\_\+of}}}.

The epsilon of a floating-\/point type is given by {\ttfamily Info\+::epsilon()}, while that of an integral type is {\ttfamily T(1)}. The classification of {\ttfamily T} is based on {\ttfamily Info}, which can be replaced by a class type that provides the same interface as {\ttfamily std\+::numeric\+\_\+limits}.

Calculation is based on {\ttfamily From\+Info} and {\ttfamily To\+Info}, which default to respective instantiations of {\ttfamily std\+::numeric\+\_\+limits}. They can be replaced by class types that provide the same interface as {\ttfamily std\+::numeric\+\_\+limits}. \begin{DoxyRemark}{Remarks}
This does not check if {\ttfamily From} is actually convertible to {\ttfamily To}.
\end{DoxyRemark}
The static member function only has overloads for
\begin{DoxyEnumerate}
\item {\ttfamily \mbox{\hyperlink{conceptutils_1_1integer__like}{utils\+::integer\+\_\+like}}} types, and
\item {\ttfamily \mbox{\hyperlink{structutils_1_1integer}{utils\+::integer}}} instances with identical behavior profiles.
\end{DoxyEnumerate}

{\ttfamily \mbox{\hyperlink{structutils_1_1integer}{utils\+::integer}}} can be compared with an {\ttfamily \mbox{\hyperlink{conceptutils_1_1integer__like}{utils\+::integer\+\_\+like}}} type if and only if both have the same signedness (either both signed, or both unsigned).
