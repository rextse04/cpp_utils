\subsubsection*{template$<$typename T, bool Sync = false$>$\newline
class utils\+::pmr\+::stack\+\_\+allocator$<$ T, Sync $>$}
An allocator which allocates memory from a pre-\/allocated buffer in a lazy-\/stack-\/like manner. 

A stack allocator allocates memory from a pre-\/allocated buffer in a lazy-\/stack-\/like manner. Specifically, a memory chunk is only recycled if it is the most recent allocation; otherwise, it is simply marked \char`\"{}removed\char`\"{}. When deallocation is requested, the allocator recursively frees memory chunks in a LIFO manner until it finds a chunk that is still in use.

Internally, an implementation-\/defined control structure is constructed at the beginning of the (aligned) buffer, and one is attached to every allocated memory chunk. The control at the beginning stores a pointer to the control of most recent chunk and a pointer to the end of the buffer. For others, each one stores a pointer to the structure attached to the previous chunk, and a pointer to the object itself (or nullptr if the chunk is marked \char`\"{}removed\char`\"{}). Note that there may be gaps between a control structure and its associated object due to alignment. The following diagram is a simple diagram illustrating the allocation strategy\+: 

All instances of this class satisfy \mbox{\hyperlink{BufferAllocator_8md}{\texorpdfstring{$<$}{<}i\texorpdfstring{$>$}{>}Buffer\+Allocator\texorpdfstring{$<$}{<}/i\texorpdfstring{$>$}{>}}} and {\ttfamily resource\+\_\+allocator}. Instances with {\ttfamily Sync} equal to {\ttfamily true} also satisfy \mbox{\hyperlink{BufferAllocator_8md}{\texorpdfstring{$<$}{<}i\texorpdfstring{$>$}{>}Convertible\+Allocator\texorpdfstring{$<$}{<}/i\texorpdfstring{$>$}{>}}}. Deallocates previously allocated memory and recycles it in a LIFO manner. 

Formally, let $(M_1,M_2,...,M_k)$ be the memory chunks previously allocated by any allocator equal to {\ttfamily $\ast$this} which have not been {\itshape recycled}, in the order of allocation. A memory chunk is {\itshape recycled} if {\ttfamily allocate} can use its storage. As noted in the documentation of the class, deallocation in {\ttfamily \mbox{\hyperlink{classutils_1_1pmr_1_1stack__allocator}{stack\+\_\+allocator}}} does not always recycle memory but may simply mark it as {\itshape removed}. Let \$\+D\+\_\+i\$ indicate if \$\+M\+\_\+i\$ has been removed for $i\in[k]$. A call to {\ttfamily deallocate} first finds $t$ such that {\ttfamily p} points to $M_t$, marks the chunk as removed, then recycles all chunks in the set $\{M_i\mid D_i,...,D_k\}$. \begin{DoxyRemark}{Remarks}
The alignment argument is unused. It is defined to deallocate a pointer obtained through aligned allocation without passing the required alignment. 
\end{DoxyRemark}
